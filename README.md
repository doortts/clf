# clf

Claude Code 데스크톱 앱의 **계정별 남은 한도**를 macOS 메뉴바에 띄운다.

![메뉴바](docs/images/menubar.png)

앱은 지금 쓰는 계정 하나만 보여준다. 나머지가 얼마나 남았는지는 일일이
전환해 봐야 안다. clf 은 토큰이 캐시된 계정 전부를 한 번에 읽는다.
**추론 요청을 보내지 않으므로 조회에 토큰을 쓰지 않는다.**

---

## 무엇이 보이나

<img src="docs/images/popover.png" width="340" alt="팝오버">

계정마다 **5시간 / 주간 전체 / 주간 Fable** 세 창의 잔여와 리셋 시각.
리셋 줄에는 그 창이 어디쯤인지도 함께 적는다 (`리셋: 39%, 4일 6시간 뒤`).
남은 시간만으로는 5시간 창의 10분과 주간 창의 10분이 구별되지 않는다.
Enterprise 처럼 시간 창이 없는 플랜은 **월 예산**을 대신 보여준다
([12 문서](docs/design/12-enterprise-spend.md)).

메뉴바 막대는 코드, 숫자, 눈금 게이지 세 줄이다. 눈금 한 칸이 5% 다.

| 잔여 | 색 |
|---|---|
| 30% 이상 | 초록 |
| 15% 이상 | 기본색 |
| 5% 초과 | 노랑 |
| 5% 이하 | 빨강 |

무채색 구간은 "노랑이 곧 온다" 는 예고 자리다. 주간 Fable 창은 여유 구간에서만
초록 대신 파랑이라 세 줄이 색으로 갈린다. 치수와 색 근거는
[11 문서](docs/design/11-menubar-app.md).

## 설치

[릴리즈 페이지](https://github.com/doortts/clf/releases)에서 DMG 를 받아
`clf.app` 을 `~/Applications` 에 끌어다 놓는다. 애플 공증을 받은 빌드라 경고
없이 열린다. macOS 13 이상.

소스에서 빌드하려면 Swift 6 툴체인이 필요하다. Xcode 프로젝트는 없다.

```bash
./scripts/install-app.sh && open ~/Applications/clf.app
```

`~/Applications` 에 두는 이유는 로그인 항목 등록 때문이다. 빌드 디렉토리에
있으면 다음 빌드에 번들이 지워져 등록이 헛일이 된다.

## 설정

<img src="docs/images/settings.png" width="340" alt="설정">

톱니를 누르면 팝오버 왼쪽에 펼쳐진다.

- **메뉴바에 표시할 계정**: 범위를 고르는 칸과 계정 목록, 순서가 한 묶음이다.
  `창이 열려있는 계정만` 은 기본 창과 우리가 띄운 창을 따라가고,
  `설정에서 지정한 계정` 은 목록에서 켠 것을 그린다. 기준이 다르므로 목록 밑
  한 줄이 지금 그 목록이 막대를 정하는지 알려준다
- **메뉴바 구성**: 기본 / 도트만 / 숫자만 / 코드만
- **표시 기준**: 남은 용량 / 사용률. 색은 어느 쪽이든 잔여 기준이다
- **리셋 표기**: 숫자 옆에 남은 시간 / 리셋 시각
- 로그인할 때 실행, 한도가 바닥나면 알림
- **업데이트**: 새 버전을 확인하고 받아서 갈아 끼운다. 끝나면 앱이 다시 뜬다
  ([14 자동 업데이트](docs/design/14-self-update.html))
- **저장소**: 이슈와 릴리즈 노트로 가는 링크
- **새 창용 데이터 디렉토리 삭제**: 계정별 창이 쌓아 둔 `~/.claude-alt-*` 를 지운다

설정은 `~/Library/Application Support/clf/desktop.json` 에 저장된다.
보여줄 목록이 아니라 **숨길 목록**을 담으므로 계정이 새로 생기면 자동으로 보인다.

## 알림

한 계정에 세 번이다. **빨강에 들어설 때**(잔여 5% 이하), **다 썼을 때**,
**리셋으로 다시 쓸 수 있게 됐을 때**.

리셋 자체는 소식이 아니다. 5시간 창은 하루에도 몇 번씩 리셋되고 그때마다
알리면 알림을 꺼 버린다. 빨강을 겪은 계정이 실제로 풀렸을 때만 알리고,
5시간 창이 리셋돼도 주간이 소진이면 조용하다. 판단은 늘 막고 있는 창의
잔여로 한다.

## 세션 다루기

팝오버 아래 `작업이전/자동재개` 를 누르면 창이 뜬다. 탭이 둘이다.

**작업 이전.** 한도에 걸려 멈춘 대화를 다른 계정 창으로 옮긴다. 대화를
복사하지 않는다. 대화 본문은 `~/.claude/projects` 에 하나뿐이고 계정은 폴더
경로로만 갈리므로 420바이트짜리 레코드 한 장을 옮긴다. 73MB 대화도 즉시
끝난다 ([13 문서](docs/design/13-multi-instance.md)).

**양쪽에 두기.** 옮기는 대신 레코드를 두 계정에 함께 둔다. 리셋될 때마다 도로
옮겨 오는 왕복이 사라진다. 전제는 "동시에 쓰지 않는다" 이고, 동시에 쓰는
순간이 바로 알아야 할 사고라서 그때 경고한다
([14 세션 공유](docs/design/14-shared-session.md)).

**자동 재개.** 리밋으로 멈춘 CLI 세션을 리셋 3분 뒤에
`claude --resume <세션ID> -p "<프롬프트>"` 로 한 턴 이어 돌린다. 5시간과 주간
전체 두 창이 모두 잔여 5% 이상일 때만 실행하고, 모자라면 보류하고 그 사유를
남긴다. 마지막 남은 몫은 사람이 쓸 자리다
([16 문서](docs/design/16-auto-resume.md)).

지켜보는 계정과 CLI 로그인 계정이 다르면 남의 한도로 조용히 돈다. 그래서 탭을
열 때마다 `claude auth status` 로 물어보고 창 아래 한 줄로 적는다.

## 하지 않는 것

- **추론 요청을 보내지 않는다.** 부르는 것은 Usage API 하나다
- **계정을 자동으로 바꾸지 않는다.** 대신 계정마다 창을 따로 띄운다. 기본 창은
  그대로 두고 다른 계정에서 이어서 일할 수 있다
- **대화 내용에 손대지 않는다.** 사용량을 읽는 경로는 읽기 전용이고, 쓰는 것은
  세션 레코드(대화를 가리키는 포인터)뿐이다
- **토큰을 갱신하지 않는다.** 데스크톱 앱이 하게 두고 만료되면 그 사실만 말한다

요청도 아낀다. 한 번 읽을 때 요청이 계정 수만큼 나가기 때문이다. 기본 5분,
세 번 연속 변화가 없으면 10분, 429 를 받으면 15분. 사람이 유발한 읽기는 60초
정숙 구간. 계정 이름은 한 번만 조회하고 캐시한다. 계정 전환은 로컬 쿠키로
5초마다 확인해서 네트워크를 안 탄다. 읽기에 실패해도 마지막 값을 지우지 않고
낡았다고 표시한다.

## clfctl

앱 없이 같은 데이터를 보는 도구다. 개발과 점검에 쓴다.

```bash
./scripts/install-clfctl.sh
```

```
clfctl desktop usage              계정별 잔여
clfctl desktop usage --json       기계가 읽을 형태로
clfctl desktop orgs               아는 계정과 표시 여부
clfctl desktop hide <이름|uuid>    목록에서 뺀다
clfctl desktop show <이름|uuid>    다시 보이게 한다
clfctl desktop order <이름...>     표시 순서
clfctl desktop bar <window|chosen> 막대에 그릴 범위
```

메뉴바 숫자와 `clfctl desktop usage` 는 항상 같은 값을 낸다. `clfctl` 이
소스보다 낡았으면 실행할 때 알려준다.

## AI 와 함께 일하기

### 코드를 읽힐 때

읽는 순서를 정해 주는 것이 가장 크게 먹힌다.

1. `CLAUDE.md`: 문자 규칙과 커밋 규칙
2. [00 범위](docs/design/00-scope.md): **데스크톱 트랙과 터미널 트랙이 갈린다.**
   01 부터 07 까지는 방향이 바뀌기 전에 쓴 터미널 트랙 문서다. 이걸 먼저
   갈라 주지 않으면 제품에 없는 프록시 코드를 고치기 시작한다
3. 기능 문서 -> `Sources/ClfDesktop/<기능>.swift` -> 같은 이름의 테스트

판단은 전부 `ClfDesktop` 에 있고 `ClfApp` 에는 뷰와 상태 하나뿐이다. 잔여 계산,
이름 줄이기, 남은 시간 표기가 모두 순수 함수라 **테스트가 명세다.** 동작이
궁금하면 `Tests/ClfDesktopTests` 의 테스트 이름부터 읽힌다.

"왜 이렇게 했나" 는 코드 주석과 설계 문서에 있고 대개 문서 번호를 달아 뒀다.
주석에 `docs/design/...` 이 보이면 그 문서가 근거다.

| 타겟 | 담는 것 | 안 담는 것 |
|---|---|---|
| `ClfCore` | 순수 판정(계정 선택, 응답 분류, SSE, 헤더). **의존성 0** | 파일, 네트워크 |
| `ClfStore` | 우리 파일과 키체인 읽기, 원자적 쓰기 | 데스크톱 앱의 것 |
| `ClfDesktop` | 데스크톱 앱 상태 읽기와 앱의 모든 판단 | 뷰 |
| `ClfApp` | SwiftUI 뷰와 `UsageModel` | 판단 |
| `ClfProxy` | 터미널 트랙 프록시(NIO) | 제품 경로 |
| `clfctl` | 위를 손으로 돌려보는 CLI | 판단 |

물어볼 때 문서 절 번호까지 집어 주면 헛짚지 않는다.

```
docs/design/16-auto-resume.md 3절을 읽고, 보류 사유를 화면에 남기는 코드가
AutoResumeDriver 와 ResumeTab 중 어디에 있는지 찾아. 고치기 전에 관련 테스트
이름을 먼저 보여줘.
```

### PR 을 보낼 때

- `swift test` 가 통과해야 한다. **새 판단에는 테스트를 먼저 쓴다.** 뷰에는
  판단을 두지 않는다. 뷰는 테스트할 수 없기 때문이다
- 커밋은 Conventional Commits, 스코프는 모듈이나 디렉토리 이름
  (`app`, `desktop`, `core`, `scripts`, `docs`)
- 커밋 하나에 한 가지. 리팩터링과 기능을 같은 커밋에 섞지 않는다
- **작성 도구를 밝히는 trailer 를 넣지 않는다.** `Co-Authored-By` 도 해당한다
- 문서와 주석에는 타이핑할 수 있는 문자만 쓴다. 검사 명령이 `CLAUDE.md` 에 있다
- 화면을 바꾸면 시안 HTML 을 `docs/design/` 에 두고 커밋 메시지에서 가리킨다.
  기존 시안이 그 형식의 견본이다

설계가 바뀌는 변경이면 코드보다 문서가 먼저다. 문서를 고치게 하고, 그 문서를
근거로 코드를 짜게 한다. 순서를 뒤집으면 근거 없는 코드가 남는다.

## 개발

```bash
swift test
```

```
./dev.sh                    디버그 빌드로 이 터미널에 붙여 띄운다
./dev.sh desktop usage      앱 대신 clfctl 을 부른다
./scripts/install-app.sh    ~/Applications 에 설치
./scripts/make-app.sh       .app 번들만 만든다
```

릴리즈는 `scripts/release.sh` 가 태그부터 릴리즈 게시까지 한 판에 한다.
Developer ID 서명과 애플 공증(앱과 DMG 각각)이 들어가므로 인증서와 notarytool
키체인 프로필이 필요하다. 준비물은 스크립트 머리 주석에 있다.

```bash
./scripts/release.sh v0.4.0 --publish
```
