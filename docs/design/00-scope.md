# 00. 지금 무엇을 만들고 있나

이 문서를 먼저 읽는다. 01 부터 07 까지는 방향이 바뀌기 전에 쓴 것이라
지금 만드는 것과 다르다.

---

## 1. 만드는 것

**Claude Code 데스크톱 앱의 계정별 잔여를 메뉴바에 보여주는 앱.**

```
84%
```

누르면 계정마다 세 줄이 나온다. 5시간, 주간 전체, 주간 모델별.
활성 계정만이 아니라 **토큰이 캐시된 계정 전부**를 읽는다. 앱은 활성 계정
하나만 보여주므로 나머지가 얼마나 남았는지는 원래 일일이 전환해 봐야 안다.

**추론 요청은 보내지 않는다.** 우리가 부르는 것은 Usage API 하나다.

여기에 계정별 창이 붙었다. 계정마다 데이터 디렉토리를 따로 준 인스턴스를
띄우고, 한도에 걸린 대화를 남은 계정으로 넘긴다. [13 문서](13-multi-instance.md).

**처음에는 "읽기만 한다" 고 적었는데 그 전제는 깨졌다.** 세션 레코드를 옮기는
두 자리(`SessionMirror`, `SessionHandoff`)가 데스크톱 앱의 데이터 디렉토리에
쓴다. 사용량을 읽는 경로는 지금도 읽기 전용이고, 쓰는 것은 420바이트짜리
레코드뿐이며 대화 내용에는 손대지 않는다.

그 뒤에 셋이 더 붙었다. 한 대화를 두 계정에 함께 두는 **세션 공유**
([14 문서](14-shared-session.md)), 리셋을 기다려 CLI 로 세션을 이어 돌리는
**자동 재개**([16 문서](16-auto-resume.md)), 그리고 앱이 스스로 새 버전으로
갈아타는 **자동 업데이트**([14 자동 업데이트](14-self-update.html))다.

## 2. 만들려다 그만둔 것

**한도에 걸리면 계정을 자동으로 바꿔주는 프록시.** 원래 이것이 제품이었고
01 부터 07 까지가 그 설계다.

두 번 막혔다.

### 첫째, 데스크톱 앱은 프록시를 안 탄다

`settings.json` 의 `env.ANTHROPIC_BASE_URL` 로 트래픽을 우리 포트로 돌리는
방식인데, 데스크톱 앱이 그걸 무시한다. 자식 프로세스 환경에 값을 직접 꽂고
그 이름을 관리 대상 변수로 잠가 둔다.

프로세스 환경에까지 넣고 시험했지만 요청 0건이었고, 앱 로그에는
`apiHost: 'https://api.anthropic.com'` 이 찍혔다.
근거는 [08 검증](08-verification.md) 7-4절.

터미널 `claude` 는 `settings.json` 을 따른다. 프록시는 그쪽에서 동작한다.

### 둘째, 바꿀 수 있어도 바꾸면 안 된다

`lastActiveOrg` 쿠키를 고치고 앱을 재시작하면 계정이 바뀐다. 실제로 확인했다.
[09 문서](09-desktop-org-switch.md) 참고.

그런데 **재시작이 필요하고 대화 이력이 끊긴다.** 작업하는 도중에 계정이 저절로
바뀌고 하던 이야기가 사라지면, 한도에 걸려 잠깐 기다리는 것보다 불편하다.
문제보다 해법이 큰 경우다. 그래서 안 한다.

**나중에 이 전제가 깨졌다.** 인스턴스를 하나 더 띄우면 계정을 동시에 쓸 수
있고 맥락도 옮길 수 있다. 끊기는 것이 아니라 옮겨 앉는 것이 된다.
[13 문서](13-multi-instance.md) 참고. **조사로 시작했지만 지금은 제품에
들어와 있다.** 팝오버에서 계정마다 창을 띄우고 앞으로 꺼내며, 세션을 다른
계정으로 넘긴다. 자동 전환을 안 한다는 결론은 그대로다. 창을 띄우고 세션을
옮기는 것은 사용자가 누를 때만 한다.

앱 자신의 드롭다운은 재시작 없이 바꾼다(pid 가 안 변한다). 재시작은 앱의
제약이 아니라 우리 방식의 대가다.

## 3. 두 갈래

| | 데스크톱 트랙 | 터미널 트랙 |
|---|---|---|
| 대상 | Claude Code 데스크톱 앱 | 터미널 `claude` |
| 하는 일 | 사용량을 보여주고, 계정별 창을 띄우고, 세션을 옮기고 공유하고 이어 돌린다 | 프록시가 한도 보고 계정을 바꾼다 |
| 상태 | **지금 만드는 제품** | 코드는 있고 테스트는 통과. 제품으로는 안 내놓음 |
| 문서 | 09 - 17 | 01 - 07 |

터미널 트랙 코드를 지우지 않는다. 동작하고, 테스트가 지식을 담고 있고,
언젠가 쓸 수 있다. 다만 지금 제품은 아니다.

**보관**은 그 시점의 판단을 남긴 기록이라 지금과 다르며, **참고**는 남의 것을
뜯어본 문서다. 이 열이 이 저장소에서 문서 최신 여부를 말하는 유일한 자리다.

## 5. 고친 기록을 지우지 않는다

01 부터 07 까지를 다시 쓰지 않고 남긴다. 틀린 대목에는 그 자리에 정정을 붙인다.

무엇을 왜 믿었고 어떻게 틀렸는지가 결론만큼 쓸모 있다. 특히 프록시가 막힌
과정은 증거를 모으는 방법 자체가 기록으로 남을 만하다. 처음에 나는 약한
근거로 막혔다고 단정했고, 되묻는 질문을 받고서야 제대로 시험했다.
