# 13. 두 계정을 동시에, 맥락을 옮겨서

[09 문서](09-desktop-org-switch.md)에서 자동 전환을 접었다. 이유는 하나였다.

> 재시작이 필요하고 대화 이력이 끊긴다

그 전제가 틀렸다. 이 문서는 그것을 뒤집는 과정이다.

---

## 1. 딥링크가 있다

앱이 `claude` URL 스킴을 등록해 두고 있다.

```
plutil -extract CFBundleURLTypes json -o - /Applications/Claude.app/Contents/Info.plist
-> [{"CFBundleURLName":"Claude","CFBundleURLSchemes":["claude"]}, ...]
```

세션과 관련된 경로가 셋이다. 전부 실제로 던져서 확인했다.

| 경로 | 하는 일 | 결과 |
|---|---|---|
| `claude://code/new?q=&folder=` | 새 세션. 프롬프트와 폴더 지정 | 된다 |
| `claude://resume?session=<uuid>` | CLI 트랜스크립트를 가져와 연다 | **된다** |
| `claude://code/<cse_\|session_>` | 브리지 세션 | 기능 플래그로 잠김 |

셋째가 잠긴 것은 대조 실험으로 확정했다. 게이트가 없는 `resume` 에 없는 uuid 를
주면 오류 토스트가 뜬다.

```
Couldn't open that session. Its transcript may have been removed.
```

`cse_` 쪽은 아무 반응이 없었다. 앱이 딥링크 실패에 반응은 하므로, 무반응은
그 앞에서 막혔다는 뜻이다.

---

## 2. 계정은 프로세스 전역이다

드롭다운으로 계정을 바꾸면 **돌고 있던 세션이 그 자리에서 끊긴다.** 왜인지가
코드에 있다.

```js
this.currentOrgId = s;
await this.migrateLegacySessions();
await this.loadSessions();          // 세션 맵을 통째로 갈아끼운다
```

`currentOrgId` 는 메인 프로세스의 매니저에 있는 필드 **하나**다. 창을 몇 개
띄우든 같은 값을 본다. 창을 더 여는 것으로는 해결이 안 된다.

`Partitions` 디렉토리가 있어 기대했지만 `cowork-file-preview` 와
`launch-preview-static` 둘뿐이다. 미리보기 렌더링용이지 계정 격리용이 아니다.

---

## 3. 그런데 인스턴스는 여러 개 뜬다

두 가지를 찾았다.

**하나. 단일 인스턴스 잠금이 없다.** 번들 전체에 `requestSingleInstanceLock` 이
없다. 두 번째 프로세스가 그냥 뜬다.

**둘. 데이터 디렉토리를 환경변수로 바꿀 수 있다.**

```js
if (process.env.CLAUDE_USER_DATA_DIR) {
  const A = process.env.CLAUDE_USER_DATA_DIR;
  app.setPath("userData", A);
  app.setPath("logs", resolve(A, "Logs"));
}
```

그래서 이렇게 하면 두 계정이 동시에 산다.

```
CLAUDE_USER_DATA_DIR=~/.claude-alt \
  nohup /Applications/Claude.app/Contents/MacOS/Claude &
```

쿠키가 따로이므로 `lastActiveOrg` 도 따로다. 실측으로 확인했다.

```
기본: 746e81ae-...  (NAVER_TEAM_40)
alt : 2a063dae-...  (NAVER_TEAM_52)
```

원래 인스턴스는 멀쩡하고 돌던 세션도 안 끊긴다. **서로 남남이기 때문이다.**

`open` 으로는 안 된다. LaunchServices 가 셸 환경을 안 물려준다. 실행 파일을
직접 띄워야 환경변수가 먹는다.

### 씨앗은 44K 면 된다

처음에는 빈 디렉토리로 띄워 새로 로그인했다. 그럴 필요가 없다. 로그인은
쿠키에 있고 계정별 토큰은 `config.json` 에 있다. 넷만 복사하면 된다.

```
Cookies        sqlite backup API 로 일관된 사본을 뜬다. 앱이 열고 있다
config.json    계정별 OAuth 토큰 캐시
Local State
Preferences
```

합쳐서 **44K** 다. 여기에 `lastActiveOrg` 를 원하는 계정으로 미리 박아 두면
**로그인 화면 없이 그 계정으로 뜬다.** 확인했다.

띄우고 나면 앱이 스스로 채운다.

| | | |
|---|---|---|
| `claude-code` | 245M | CLI 바이너리를 인스턴스마다 새로 푼다 |
| `Cache` | 59M | 지워도 다시 생긴다 |
| 나머지 | 7M | |

245M 는 줄일 방법이 없다. 심볼릭 링크로 기본 쪽을 가리키면 두 인스턴스가
같은 파일을 쓰게 되어 2절의 잠금 문제와 같은 위험이 생긴다.

### 같은 디렉토리를 공유하는 것은 안 된다

인스턴스만 하나 더 띄우고 데이터 디렉토리는 그대로 쓰면 어떨까. 안 된다.

기본 인스턴스가 LevelDB 잠금을 배타적으로 쥐고 있다.

```
39u  Local Storage/leveldb/LOCK
40u  Session Storage/LOCK
51u  IndexedDB/https_claude.ai_0.indexeddb.leveldb/LOCK
```

그리고 되더라도 쿠키가 같으니 두 인스턴스가 **같은 계정**을 본다. 목적을
못 이룬다.

## 4. 세션 레코드는 포인터일 뿐이다

저장소가 사람과 계정별로 갈려 있다.

```
claude-code-sessions/
  914e4f12-...(계정)/
    746e81ae-...(NAVER_TEAM_40)/
      local_6fcb1fa1-....json
```

```js
getStorageDir() { return join(userDataPath, baseDir, currentAccountId, currentOrgId) }
```

그런데 그 파일 안에 **대화 내용이 없다.**

```json
{
  "sessionId": "local_6fcb1fa1-...",
  "cliSessionId": "6fcb1fa1-...",
  "cwd": "/Users/cpm4/repos/clfl",
  "originCwd": "/Users/cpm4/repos/clfl",
  "lastFocusedAt": 1785648947052,
  "createdAt": 1785646596237,
  "lastActivityAt": 1785646596237,
  "isArchived": false,
  "permissionMode": "default",
  "remoteMcpServersConfig": [],
  "alwaysAllowedReasons": [],
  "sessionPermissionUpdates": []
}
```

내용은 `~/.claude/projects/<프로젝트>/<cliSessionId>.jsonl` 에 있다.
**그 경로는 `CLAUDE_USER_DATA_DIR` 밖이라 인스턴스끼리 공유된다.**

세션 레코드는 "이 사람의 이 계정에서 저 트랜스크립트를 보여줘라" 는 포인터다.
그래서 같은 트랜스크립트를 계정마다 따로 가리킬 수 있다.

Fork 도 같은 원리다. 서버 기능이 아니라 트랜스크립트 파일 복사다.

```js
copyTranscriptUntil(src, dest, uuid)   // 그 메시지 전까지만
await copyFile(src, dest)              // 통째로
```

## 5. 그래서 맥락이 계정을 건너간다

`loadSessions()` 가 하는 일은 디렉토리를 읽는 것뿐이다. 인덱스도 서명도 없다.

```js
const c = await readdir(e);
r = Array.from(l).filter(u => u.startsWith("local_") && u.endsWith(".json"));
```

그래서 레코드를 직접 써 넣으면 앱이 다음 기동에 읽는다.

```
~/.claude-alt/claude-code-sessions/<계정>/2a063dae-.../local_<cliSessionId>.json
```

**확인했다.** 비어 있던 alt 인스턴스(NAVER_TEAM_52)의 목록에 세션이 나타났고,
열었더니 대화 내용과 작업 폴더와 git 브랜치까지 그대로 왔다.

```
1. CLAUDE_USER_DATA_DIR 로 두 번째 인스턴스를 띄운다
2. 거기서 다른 계정으로 로그인한다              (최초 한 번)
3. 세션 레코드를 써 넣고 그 인스턴스만 재시작한다
   -> 원래 창은 살아 있고 맥락은 다른 계정에서 이어진다
```

접었던 이유가 사라진다. 드롭다운 전환과 달리 **끊기는 것이 아니라 옮겨 앉는
것**이 된다.

## 6. 확인한 것과 안 한 것

| | |
|---|---|
| 두 인스턴스 동시 실행 | 확인 |
| 계정이 서로 독립인가 | 확인. 쿠키를 각각 읽었다 |
| 원래 세션이 안 끊기는가 | 확인. 이 대화가 그 인스턴스에서 돌고 있었다 |
| 레코드 주입으로 세션이 뜨는가 | 확인 |
| 맥락이 오는가 | 확인. 대화, 폴더, 브랜치 |
| 이어서 대화가 되는가 | **확인.** 아래 |
| 재시작 없이 되는가 | 안 된다. 감시도 안 하고 목록 갱신이 더하기만 한다. 12절 |
| 딥링크로 alt 를 지정할 수 있는가 | **안 된다.** 먼저 뜬 인스턴스가 독점한다 |

딥링크가 독점되는 것이 레코드를 직접 쓴 이유다. macOS 는 URL 스킴을 등록된 앱
하나로만 보낸다.

### 비용은 새 계정이 낸다

alt 창에서 메시지를 보내고 양쪽 사용량을 읽었다.

```
alt 인스턴스 로그:  org 2a063dae-...      (NAVER_TEAM_52)
트랜스크립트:       claude-opus-5, 캐시 읽기 54,358 토큰
TEAM_52 5시간:      0.0 -> 2.0
TEAM_40:            안 움직임
```

맥락 전체를 싣고 나갔고 **비용은 새 계정이 냈다.** 화면만 옮긴 것이 아니다.

한 가지 곁가지를 배웠다. 처음에는 양쪽 다 안 움직인 것으로 보였다. 우리가
`limits[].percent`(정수)만 읽기 때문이다. 응답에는 `five_hour.utilization` 이
**실수**로 온다. 1% 미만 변화를 보려면 그쪽을 써야 한다.

### 트랜스크립트는 실시간으로 공유된다

주입한 뒤에 기본 인스턴스에서 오간 대화가 alt 창에도 그대로 보였다. 복사본이
아니라 **같은 파일을 양쪽이 보고 있다.**

## 7. 넘은 선

지금까지 **남의 앱 파일은 읽기만 한다**를 지켜왔다. 여기서는 썼다.

다만 쓴 곳은 **우리가 만든 두 번째 인스턴스의 데이터 디렉토리**다.
`~/.claude-alt` 는 이 실험을 위해 만든 모래상자이고, 사용자가 원래 쓰던
`~/Library/Application Support/Claude` 는 손대지 않았다.

제품으로 만든다면 이 구분을 유지해야 한다. 우리가 만든 인스턴스에만 쓰고,
사용자의 기본 인스턴스는 계속 읽기만 한다.

---

## 8. 이것이 제품에 뜻하는 것

아직 제품이 아니다. 조사 결과다. 하지만 [00 범위](00-scope.md) 2절의 판단
근거가 바뀌었으므로 적어 둔다.

접었던 이유는 "해법이 문제보다 크다" 였다. 맥락이 끊기는 대가가 한도에 걸려
기다리는 것보다 컸기 때문이다. 지금은 그 대가가 없다.

대신 새 대가가 생겼다.

- 인스턴스를 하나 더 띄워야 한다. 메모리도 두 배고 디스크도 300MB 더 쓴다
- 세션을 옮길 때마다 그 인스턴스를 재시작해야 한다
- 앱의 내부 파일 형식에 기댄다. 앱이 바뀌면 깨진다

재로그인은 안 해도 된다. 44K 씨앗으로 해결됐다.

마지막 것이 제일 무겁다. 지금 하는 일(사용량 읽기)은 형식이 바뀌면 숫자가
안 보이는 정도지만, 이쪽은 사용자의 작업 흐름 한가운데서 깨진다.

## 9. clf 이 대신 띄운다

조사에서 제품으로 넘어온 부분이다. 팝오버의 계정마다 창 상태가 붙는다.

```
NAVER_TEAM_40  [team] [기본]            [앞으로 꺼내기]
NAVER_TEAM_52  [team]  o                [앞으로 꺼내기]
Naver     [enterprise]                  [새 창 띄우기]
```

모양으로 역할이 갈린다.

| | 모양 | 뜻 |
|---|---|---|
| `team` `enterprise` `여유` | 알약 | 정보 |
| `기본` , 노란 점 | 알약과 점 | 상태 |
| `새 창 띄우기` | 사각형에 채움 | 주된 행동 |
| `앞으로 꺼내기` | 사각형에 테두리 | 부차 행동 |
| `여는 중` `이름을 못 쓴다` | 테두리 없는 상자 | 누를 수 없는 상태 |

**상태와 행동을 가른다.** 처음에는 `창 열려있음` 배지를 누르게 했다. 상태이면서
행동이라 설명 툴팁까지 달아야 했다. HIG 는 단추 라벨을 동사로 쓰라고 하므로
상태는 왼쪽에, 동작은 오른쪽 단추에 둔다.

기본 인스턴스가 쓰는 계정 표시는 세 번 바뀌었다.

| | 왜 바꿨나 |
|---|---|
| 이름을 붉게 칠한다 | 이 화면에서 빨강은 소진이다. 강조가 위험 신호로 읽혔다 |
| 이름 앞 파란 점 | 범례를 알아야 읽힌다. 폭도 16pt 먹는다 |
| 회색 `기본` 배지 | 지금. 플랜 배지 옆에 글자로 적는다 |

별도 창이 떠 있다는 표시는 반대 방향으로 갔다. `창 열려있음` 배지가 90pt 를
먹어서 계정 이름이 잘렸고, 같은 말을 오른쪽 단추가 이미 하고 있어서 노란 점만
남겼다. 문구는 접근성 라벨로 넘긴다. 폭 계산은
[11 문서](11-menubar-app.md) 4절과
[primary-badge-mockup.html](primary-badge-mockup.html).

단추 치수는 카드끼리 같다. 시스템 단추 스타일을 쓰던 동안에는 옆 카드의 상태
상자와 크기도 색도 안 맞았다. 지금은 셋 다 `controlBox` 로 그린다.

### 디렉토리 이름이 곧 목록이다

```
~/.claude-alt-NAVER_TEAM_52
```

계정 이름을 그대로 쓴다. 경로만 보고 어느 계정 것인지 알 수 있어 목록 파일을
따로 두지 않아도 되고, 그래서 어긋날 일도 없다. uuid 를 쓰면 사람이 못 읽는다.

**이름이 곧 경로이므로 한 조각으로 만든다.** 공백은 지우고 경로 구분자는
`-` 로 바꾸며 앞의 점은 떼어낸다. 점과 대시만 남으면 거부한다. `../..` 가
`..` 로 남는 경우가 있었다.

한글 이름은 그대로 둔다. 경로에 문제없는 글자다.

### 지우는 자리를 만들었다

계정마다 300MB 씩 쌓인다. 설정 아래에 `멀티 인스턴스 정보 삭제` 를 뒀다.

`~/.claude-alt-` 로 시작하는 디렉토리만 지운다. 그 접두사가 아니면 우리 것이
아니므로 손대지 않는다. **떠 있는 창의 것은 남긴다.** 쓰는 중에 지우면 그
인스턴스가 깨진다.

되돌릴 수 없으므로 **먼저 보여주고 확인을 받는다.**

```
지울 것
NAVER_TEAM_52 (316MB)
그 계정 창의 대화 목록이 사라진다. 대화 내용 자체는 남고 다시 띄우면
로그인도 유지된다

[취소]  [316MB 지운다]
```

몇 개인지가 아니라 **무엇인지** 말한다. 이름과 크기를 봐야 판단할 수 있다.
남기는 것이 있으면 그것도 말한다. 안 지워졌다고 오해하면 또 누른다.

무엇을 잃고 무엇이 남는지도 적는다. 사라지는 것은 대화 **목록**이고 대화
**내용**은 `~/.claude/projects` 에 남는다. 이 구분을 모르면 누를 수 없다.

확인 창은 팝오버 안에서 편다. `NSAlert` 를 띄우면 포커스가 옮겨가 팝오버가
닫힌다.

결과는 **누른 자리 바로 아래**에 둔다. 처음에는 팝오버 맨 위에 뒀는데 단추가
아래에 있어서 눈이 안 갔다. 그리고 팝오버를 다시 열면 지운다. 한 번 읽으면
끝인 말이 계속 남아 있으면 지금 일어난 일인지 아까 일인지 알 수 없다.

### 떠 있는 창은 프로세스에서 읽는다

```
ps -A -E -o command=
-> ... /Applications/Claude.app/Contents/MacOS/Claude CLAUDE_USER_DATA_DIR=/Users/x/.claude-alt-<uuid>
```

로컬 프로세스만 보므로 공짜다. 계정 전환 감시(5초)와 같은 자리에서 함께 훑는다.

**`-A` 를 빠뜨려서 한 번 헛돌았다.** 없으면 지금 터미널 세션의 프로세스만
나온다. 앱에서는 아무것도 안 잡혔다.

헬퍼 프로세스가 수십 개 뜨므로 실행 파일 경로로 거른다.

### 여는 중을 보여준다

245MB 를 푸느라 십수 초 걸린다. 그동안 표시가 없으면 사용자가 또 누르고
인스턴스가 둘이 된다. 눌린 순간 `여는 중` 으로 바꾸고, 2초마다 훑어 실제로
뜨면 `창 열려있음` 으로 넘긴다. 60초가 지나도 안 뜨면 표시를 거두고 말한다.

### 뜬 창을 앞으로 꺼낸다

배경 앱에서 실행하면 창이 뒤에 뜬다. 십수 초 기다린 끝에 아무 일도 안 일어난
것처럼 보이면 또 누른다.

떴다는 것을 확인한 그 자리에서 `NSRunningApplication` 으로 활성화한다. 그래서
훑을 때 pid 도 같이 뽑는다.

```
ps -A -E -o pid=,command=
-> 39733 /Applications/Claude.app/Contents/MacOS/Claude CLAUDE_USER_DATA_DIR=...
```

### 기본 창도 꺼낸다

우리가 띄운 창만 꺼낼 수 있던 동안 기본 창 자리에는 `기본` 상태 상자만 있었다.
정작 제일 자주 찾는 창인데 팝오버에서 그 창으로 돌아갈 길이 없었다.

**기본 창은 `ps` 로 못 찾는다.** 별도 인스턴스만 `CLAUDE_USER_DATA_DIR` 를 달고
있고 기본 인스턴스에는 표시가 없다. 실행 파일이 같은 프로세스 중에서 **우리가
띄운 pid 를 뺀** 나머지가 그것이다. 그 pid 목록은 모델이 이미 들고 있다.

```swift
NSWorkspace.shared.runningApplications.first {
    $0.executableURL?.path == AltInstance.executable
        && !altPIDs.contains($0.processIdentifier)
}
```

못 찾으면 데스크톱 앱이 아예 안 떠 있는 경우다. 그때는 눌린 자리 아래에 그
사실을 적는다. 단추를 미리 숨기지는 않는다. 숨기려면 `ps` 를 한 번 더 돌려야
하고, 안 떠 있는 것은 눌러 보면 알 수 있는 일이다.

### 세션 주입은 넣지 않았다

이번 범위는 **빈 창 열기까지**다. "이 대화를 저 계정으로 옮기기" 는 세션을
고르는 화면이 필요하고, 그건 팝오버 자리가 아니다.

## 10. 세션 목록을 양쪽으로 옮긴다

9절까지는 새 창이 비어 있었다. 이제 대화 목록이 따라간다.

### 띄울 때 기본 창의 목록을 심는다

새 창을 띄우면 기본 인스턴스에서 보던 세션 레코드를 그 계정 폴더에 복사한다.
레코드는 포인터일 뿐이고 트랜스크립트는 공유되므로 **같은 대화가 새 계정에서
열린다.**

```
기본  <데이터>/claude-code-sessions/<사람>/<기본 계정>/local_*.json
  ->
새 창 ~/.claude-alt-<이름>/claude-code-sessions/<사람>/<그 계정>/local_*.json
```

### 되돌리기도 한다

새 창에서 한 작업을 기본 창에서도 보려면 반대로 옮겨야 한다. 5초 감시 루프와
팝오버를 열 때 함께 돈다. 로컬 파일 복사라 싸다.

**기본 창에서 그 계정으로 바꾸면 그때 목록에 나타난다.** 앱이 계정을 바꿀 때
세션 디렉토리를 다시 읽기 때문이다.

이것이 **사용자의 기본 데이터 디렉토리에 쓰는 유일한 자리다.** 7절에서 그은
선을 여기서 넘는다. 같은 계정 폴더에 레코드만 더하고 기존 파일은 덮지 않는다.

### 파일 이름의 uuid 는 트랜스크립트 id 가 아니다

여기서 한 번 틀렸다. `local_<uuid>.json` 의 uuid 로 트랜스크립트를 찾았는데
넷 중 하나만 옮겨졌다.

```
local_071c8461-....json  ->  cliSessionId 766182af-...    다르다
local_6fcb1fa1-....json  ->  cliSessionId 6fcb1fa1-...    같다
```

앱이 직접 만든 세션은 세션 id 와 트랜스크립트 id 가 따로다. 딥링크로 가져온
것만 `local_<cliSessionId>` 라서 같아 보였다. **레코드를 열어서 `cliSessionId`
를 읽어야 한다.**

### 덮지 않는다

이미 있는 파일은 건드리지 않는다. 저쪽에서 고친 것을 덮으면 안 된다.
트랜스크립트가 없는 레코드도 뺀다. 옮겨 봐야 빈 세션이 뜨고 그건 고장으로
보인다.

## 11. 세션 넘기기

10절의 자동 미러링과 다른 기능이다. 자동은 **같은 계정 폴더끼리**만 옮기고,
이쪽은 사용자가 골라서 **계정을 건너** 넘긴다.

가장 쓸모 있는 순간은 **한도에 걸려 작업이 멈췄을 때**다. 그때 남은 계정으로
하던 일을 옮겨 이어간다.

### 복사하지 않는다. 레코드를 옮긴다

3절의 계층을 다시 본다.

| | 어디에 | 계정 표시 |
|---|---|---|
| 트랜스크립트 | `~/.claude/projects`. 인스턴스끼리 공유 | 없다 |
| 레코드 | `<데이터 디렉토리>/claude-code-sessions/<사람>/<계정>/` | **어느 폴더에 있느냐가 전부** |

대화가 어느 계정 것인지는 420바이트짜리 레코드가 어느 폴더에 있느냐로만
정해진다. 그러면 계정을 바꾸는 데 필요한 일은 **그 파일을 옮기는 것뿐**이다.

| | 복사 | 옮기기 |
|---|---|---|
| 대화 파일 | 통째로 복사. 실측 73MB 짜리가 있다 | 안 건드린다 |
| 짝 없는 tool_use | 떼어내야 한다 | 상관없다 |
| 50MB 넘는 파일 | 앱이 꼬리만 읽는다 | 상관없다 |
| 그 대화를 가리키는 계정 | 둘 | 하나 |
| 원본 | 따로 정리해야 한다 | 저절로 없어진다 |

계정 둘이 같은 대화를 가리키면 창 둘이 같은 트랜스크립트에 쓸 수 있다.
옮기면 그 걱정 자체가 없어진다.

### 자리가 여럿이다

한 계정의 레코드는 기본 데이터 디렉토리에 있고, 그 계정으로 띄운 별도 창이
있으면 거기에도 하나 더 있다(10절). 한 자리만 옮기면 남은 창이 그 세션을
계속 보여준다. 그래서 자리를 다 모아 한꺼번에 옮긴다.

**먼저 넣고 나중에 지운다.** 중간에 죽어도 대화를 잃지 않는다. 대상에 같은
이름이 하나라도 있으면 아무것도 안 바꾸고 멈춘다.

### 옮긴 뒤에 남는 일

앱은 세션 목록을 메모리에 들고 있다. 파일만 바꾸면 화면은 그대로다.

| 그 계정의 창 | 무엇을 하나 |
|---|---|
| 기본 창 | 재시작해야 반영된다고 말만 한다. 사용자 창이라 우리가 안 닫는다 |
| 별도 창 | 우리가 띄운 것이라 단추 하나로 다시 띄운다 |
| 창 없음 | 할 일이 없다. 다음에 띄우면 보인다 |

### 제목은 트랜스크립트에서 읽는다

레코드에는 제목이 없다. 목록에 뜨는 이름은 트랜스크립트 안에 있고
`customTitle` 이 `aiTitle` 을 이기며 나중 줄이 이긴다. 파일이 73MB 까지
가므로 **양끝 256KB 만 읽는다.**

### 고친 기록: 복사에서 옮기기로

처음에는 앱의 Fork 를 흉내내 트랜스크립트를 복사하려 했다. 세 갈래를 놓고
비교까지 했다.

| | 하는 일 |
|---|---|
| CLI `--fork-session` | 메시지 uuid 재생성, 부모 사슬 재연결, `forkedFrom` 기록, sidechain/progress 제거 |
| 데스크톱 앱 Fork | `copyFile` 로 줄을 그대로 복사 |

복사를 전제하니 딸린 문제가 줄줄이 나왔다. 짝 없는 `tool_use` 로 끝난 파일은
API 가 거부하므로 떼어내야 하고, 50MB 를 넘으면 앱이 꼬리만 읽으며, 복사본에
`[넘김]` 표시를 붙이고 원본을 따로 정리해야 했다.

그 과정에서 하나는 데이터로 뒤집혔다. 짝 맞추기를 `stop_reason: end_turn`
까지 자르려 했는데, 실제 트랜스크립트를 세어 보니 그러면 진행 중이던 턴
전체를 버리는 규칙이었다.

```
stop_reason=tool_use:  2,491
stop_reason=end_turn:    144
```

에이전트 세션은 한 턴에 도구를 수십 번 부르고, 한도는 대개 그 긴 턴 중간에
걸린다.

결국 전제를 의심하는 쪽이 답이었다. **넘기기는 사용자가 명시적으로 하는
일이라 그 순간 대화는 멈춰 있다.** 그러면 복사할 이유가 없고, 복사를 안 하면
위의 문제가 전부 사라진다. 짝 맞추기 판정도, 크기 한계도, 표시도 필요 없다.

먼저 만든 `TranscriptFork` 는 지웠다. 커밋 `f8cf8c6` 에 남아 있다.

넘긴 세션이 말을 이어서 하는지 8월 2일에 봤다. 된다. 6절의 마지막 칸이 이걸로

> 넘기기는 사용자가 명시적으로 하는 일이라 그 순간 대화는 멈춰 있다

트랜스크립트에는 맞다. 작업 트리에는 안 맞다. 넘긴 대화가 멈춰 있어도 같은
폴더의 **다른** 세션은 계속 쓴다.

### 이 문서를 고치다가 그대로 당했다

12절을 쓰려고 파일을 고치는데 편집이 튕겼다.

```

```

읽고 쓰는 사이에 다른 세션이 이 파일을 다시 썼다. 커밋 `16eac40` 과 `a0bbb92`
가 그 사이에 들어왔고 문서는 223줄에서 537줄이 되어 있었다.

### 지금 디스크가 11절 규칙을 어기고 있다

11절은 한 대화를 한 계정만 가리키게 한다. 지금은 아니다.

```
746e81ae-.../  local_6fcb1fa1  local_b33bd6bb  local_b0f85d85
2a063dae-.../  local_6fcb1fa1  local_b33bd6bb  local_b0f85d85
```

셋 다 양쪽에 있다. 옮기기는 먼저 넣고 나중에 지우므로 이 상태를 만들지 않고,
10절의 미러링은 같은 계정 폴더끼리라 계정을 건너지 않는다. 5절에서 손으로 써
넣은 레코드가 남은 것으로 보이지만 확정하지 못했다.

**어긴 것을 아무도 안 잡아낸다는 것이 문제다.** 규칙은 주석과 이 문서에만 있다.

### 넘긴 뒤 원본 창에 남는 줄

11절은 기본 창에 "재시작해야 반영된다" 고 말만 한다. 재시작 말고 길이 없는
이유를 번들에서 확인했다.

목록을 다시 읽는 코드가 **더하기만 한다.**

```js
if (this.deletingSessionIds.has(f.sessionId) || this.sessions.has(f.sessionId)) return;
this.sessions.set(f.sessionId, g)
```

디스크에서 사라진 레코드에 해당하는 세션을 지우지 않는다. 10절의 미러링이 잘
되는 것과 같은 이유로 지우기는 안 된다.

메모리를 비우는 자리는 하나뿐이다.

```js
if (o !== this.currentAccountId || s !== this.currentOrgId) {
  ... this.sessions.clear() ... await this.loadSessions()   // 계정 전환
} else {
  await this.loadSessions()                                 // 더하기만
}
```

2절이 적은 "드롭다운으로 바꾸면 돌던 세션이 끊긴다" 가 이 자리다. **끊기는 그
동작이 유일한 청소 수단이다.**

딥링크에도 그런 경로가 없다. 경로 상수를 다 뽑았다.

```
magic-link  new  sso-callback  mcp-auth-callback  chat  project  settings
admin-settings  customize  create  tasks  task  space  claude-code-desktop
code  design  resume  cowork  local_sessions
```

목록 새로고침도 세션 닫기도 없다. `resume` 은 열고 `new` 는 만든다.
`local_sessions` 는 딥링크가 아니라 IPC 인터페이스 이름이고 메서드마다 발신
origin 을 검사해서 밖에서는 못 부른다.

**남은 줄은 지저분한 것으로 끝나지 않는다.** 레코드는 없어졌지만 세션은
메모리에 남아 있어서 누르면 그대로 열린다. 그러면 두 창이 같은 트랜스크립트를
보게 되고 그것이 11절이 막으려던 상황이다.

그래서 방향에 차이가 생긴다. alt 창은 우리가 다시 띄울 수 있고 기본 창은
부탁만 할 수 있다. **기본에서 alt 로 넘기는 쪽이 깨끗하다.**

### 아직 안 한 것

한 작업 폴더에 세션이 여럿인 것을 사용자에게도 세션에게도 알려주지 않는다.
이번에 알아챈 것은 모델이 `git status` 를 직접 돌려봤기 때문이고 그건 운이었다.

## 13. 앱이 환경변수를 막았다. 스위치로 옮겼다

3절이 기댄 전제가 앱 업데이트로 깨졌다.

> 데이터 디렉토리를 환경변수로 바꿀 수 있다

1.40609.0 부트 코드가 패키지로 서명된 앱에서는 그 변수를 **지운다.**

```js
var KK = jH();   // CLAUDE_CDP_AUTH 를 ed25519 로 검증
E.app.isPackaged && !KK && (delete process.env.CLAUDE_USER_DATA_DIR, ...)
```

`jH()` 는 앱 개인키로 서명한 `CLAUDE_CDP_AUTH` 토큰을 요구한다. 그 키는 번들에
없고 공개키만 있다. 그래서 `CLAUDE_USER_DATA_DIR` 를 달아 띄워도 앱이 그 변수를
버리고 **기본 데이터 디렉토리로 뜬다.** 팝오버에서 다른 계정 새 창을 눌러도
지금 열린 계정과 같은 계정 창이 하나 더 뜨는 증상이 이것이다.

실측으로 확정했다. `CLAUDE_USER_DATA_DIR=~/.claude-alt-NAVER_TEAM_40` 로 띄운
프로세스가 여는 파일 42개가 전부 기본 디렉토리였고 alt 디렉토리 파일은 0개였다.

### 우회는 Electron 스위치다

`--user-data-dir` 는 Electron 이 앱 코드보다 먼저 먹는 네이티브 스위치라 위
`delete` 를 안 탄다. 앱의 금지 스위치 목록(`remote-debugging-port` 류)에도 없다.

```
/Applications/Claude.app/Contents/MacOS/Claude --user-data-dir=~/.claude-alt-<이름>
```

실측으로 확정했다. 이 스위치로 seed 한 프로필을 띄우니 그 프로세스가 alt 디렉토리
파일 91개를 열었고, 그 창은 org `746e81ae`(NAVER_TEAM_40)에 요청을 보냈다.
같은 순간 기본 앱은 `2a063dae`(NAVER_TEAM_52)였다. 두 계정이 각자 격리된 창으로
동시에 떴다.

`HOME` 을 바꾸는 길은 접었다. macOS 에서 Electron 의 userData 경로는 `HOME`
환경변수가 아니라 실제 홈을 보므로 안 옮겨지고, 옮겨진다 해도 4절의 트랜스크립트
공유(`~/.claude/projects`)까지 끊긴다. `--user-data-dir` 는 `HOME` 을 그대로 두어
그 공유를 지킨다.

씨앗과 세션 미러링과 `ps` 스캔은 그대로다. 바뀐 것은 넘기는 방법 하나뿐이라
`launch` 는 환경변수 대신 이 스위치를 넘기고, `ps` 파싱은 `CLAUDE_USER_DATA_DIR=`
대신 `--user-data-dir=` 를 찾는다.
