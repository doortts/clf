어떻게 만드나

새 도구를 들이지 않는다. hdiutil 과 osascript 만 쓴다. 지금 3절의 hdiutil create 한 줄이 이렇게 바뀐다.

  1. hdiutil create -format UDRW 로 쓸 수 있는 DMG 를 만든다. 기본값인 UDZO 는 읽기 전용이라 창 설정을 넣을 수 없다
  2. 붙인다. 배경 그림을 .background/bg.png 로 넣고 ln -s /Applications 로 링크를 만든다
  3. osascript 로 Finder 에 창 크기, 아이콘 크기, 배경 그림, 아이콘 좌표를 적는다. Finder 가 그것을 .DS_Store 에 쓴다
  4. 뗀다. hdiutil convert -format UDZO 로 읽기 전용 압축본을 만든다. 이것이 서명하고 공증할 파일이다

먼저 알아야 할 것 둘

1. Finder 자동화 권한. 3단계의 osascript 가 Finder 를 부린다. 그 기계에서 처음 돌릴 때 macOS 가 허용을 묻는다. 릴리즈는 사람이 앞에 앉아 돌리는 것이라 한 번 눌러 주면 되지만, 안 눌리면 창 설정 없이 조용히 지나가는 것이 아니라 스크립트가 거기서 멈춰야 한다. 배경 없는 DMG 가 공증까지 통과해 올라가면 되돌릴 수가 없다.

2. 이건 결정을 뒤집는 일이다. 지금 스크립트 2절에 그 링크를 넣지 않는 이유가 적혀 있다. clf 는 ~/Applications 에 사는 앱이고 창에 뜬 링크는 /Applications 로 유도한다. DMG 안에서 ~ 를 가리키는 링크는 만들 수 없다. 만든 기계의 홈 경로가 그대로 박히기 때문이다.

/Applications 로 가도 앱은 정상으로 돈다. 실측으로 확인했다.

검사결과
UpdateInstaller.canReplace /Applications 는 admin 그룹 쓰기 가능. 자동 업데이트가 그대로 된다
LoginItem.swift:64 의 path.contains("/Applications/") /Applications/ 와 ~/Applications/ 둘 다 맞는다. 로그인 항목 등록이 된다

관리자가 아닌 계정에서만 자동 업데이트가 막히고, 그 경우는 앱이 이미 직접 받기 로 안내한다. 대신 README 와 docs/design/11-menubar-app.md 의 설치 위치 안내를 같이 고쳐야 한다. 두 곳이 ~/Applications 를 말하고 있다.
