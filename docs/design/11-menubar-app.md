# 11. 메뉴바 앱

[10 문서](10-desktop-usage.md)에서 데이터 계층을 다 만들었다. 남은 것은 화면이다.

---

## 1. Xcode 프로젝트를 두지 않는다

앱 번들은 세 가지만 있으면 된다.

```
clf.app/Contents/MacOS/clf          SPM 이 만든 실행 파일
clf.app/Contents/Info.plist          LSUIElement 로 Dock 아이콘을 없앤다
clf.app/Contents/Resources/clf.icns 아이콘
                                      임시 서명. 없으면 실행이 막힌다
```

### 아이콘은 코드로 그린다

`tools/make-icon.swift` 가 CoreGraphics 로 그리고 `make-app.sh` 가 `iconutil` 로
`.icns` 를 만든다. 산출물은 커밋하지 않고 소스가 바뀔 때만 다시 만든다.
색과 비율을 고치려면 파일을 열어 숫자를 바꾸고 다시 돌리면 된다.

그림은 잔여 막대 셋이다. 팝오버가 보여주는 것과 같은 모양이라 목록에서 봐도
무엇인지 안다.

**Dock 에 안 뜨는 앱에 아이콘이 왜 필요한가.** 메뉴바 관리 앱(Bartender 류)의
항목 목록이 이걸로 줄을 그린다. 아이콘이 없으면 이름 없는 빈 줄이 되어
35개 목록에서 사용자가 못 찾는다. 실제로 그래서 못 찾았다.

Xcode 프로젝트를 두면 타겟 정의가 `Package.swift` 와 두 곳으로 갈라지고,
커맨드라인에서 빌드가 안 된다. `scripts/make-app.sh` 가 손으로 조립한다.

```
./scripts/make-app.sh          릴리스로 빌드하고 번들을 만든다
./scripts/make-app.sh debug    디버그로
open .build/clf.app
```

`ClfApp` 은 평범한 SPM 실행 타겟이다. `swift build` 로 컴파일 오류를 바로 본다.

## 2. 무엇이 어디에 있나

| | |
|---|---|
| `ClfDesktop` | 읽기, 설정, 주기, 글자 만들기. 전부 테스트 가능 |
| `ClfApp` | SwiftUI 뷰와 상태 하나 |

뷰에서 테스트할 것이 남지 않게 갈랐다. 잔여를 몇 퍼센트로 쓸지, 이름을 어떻게
줄일지, 리셋까지 몇 시간인지는 전부 순수 함수라 `ClfDesktopTests` 가 잠근다.
`ClfApp` 에는 판단이 없다.

`UsageModel` 하나가 읽기와 설정과 주기를 쥔다. 뷰는 읽기만 한다.

## 3. 막대

[ui-spec.html](ui-spec.html) 의 "기본" 모드 그대로다.

```
T40  91%  ::::::::::::::::::
     84%  ::::::::::::::
          ::::::::::::::::::
```

코드 12pt, 숫자 9pt 두 줄(5시간과 주간), 게이지 세 줄.

**숫자와 블록을 함께 두는 이유.** 메뉴바 높이에 들어가는 숫자는 두 줄이
한계인데 계정을 묶는 창은 셋이다. 숫자만 두면 셋째 창이 안 보이고, 블록만
두면 정확한 값을 못 읽는다.

폭과 정보량은 맞바꿀 수밖에 없어서 노브 대신 넷 중 하나를 고르게 한다.

| 모드 | 보이는 것 | 대략 폭 |
|---|---|---|
| 기본 | 코드, 숫자 두 줄, 블록 세 줄 | 120pt |
| 도트만 | 코드와 블록 | 103pt |
| 숫자만 | 코드와 숫자 | 87pt |
| 코드만 | 코드 하나 | 46pt |

이것과 별개로 계정을 몇 개 올릴지가 있다. 기본은 활성 하나다.

### 앞 창의 계정에 밑줄

지금 앞에 있는 창이 어느 계정 것인지 코드 아래 1.5pt 파란 밑줄로 말한다.
시안은 1pt 를 권했지만 실기기에서 너무 얇아 한 단 올렸다.
기본 창이 앞이면 활성 계정에, 별도 인스턴스 창이 앞이면 그 계정에 붙고,
Claude 창이 하나도 앞에 없으면 지운다. 밑줄은 "지금 이 창" 이라는 말이라
남겨두면 거짓말이 된다. 파랑은 등급색과 안 겹치는 신호색이라 상태가 아니라
위치를 말한다는 것이 색으로 갈린다. focus-underline-mockup.html

### 코드는 집합에 딸린 값이다

겹치는지 알아야 정할 수 있어서 이름 하나만 보고는 못 만든다.

| 이름 | 코드 | 규칙 |
|---|---|---|
| `NAVER_TEAM_40` | `T40` | 끝 숫자와 앞 낱말 첫 글자 |
| `team1` | `T1` | 낱말과 숫자가 붙어 있어도 가른다 |
| `Naver` | `Na` | 숫자가 없으면 앞 두 글자 |
| `Naver` + `Nasdaq` | `N2` `N1` | 겹치면 첫 글자에 알파벳순 순번 |

순번이 목록 차례를 따르면 계정이 늘고 줄 때마다 코드가 흔들려 눈이 못
따라간다. 그래서 알파벳순이다.

시안은 `team` 이 든 이름에 알파벳순 번호를 붙이라고 했다(`team1` -> `T1`).
이름이 이미 번호를 달고 있으면 그쪽을 쓴다. `NAVER_TEAM_40` 을 `T1` 로 쓰면
앱 드롭다운에서 보는 40 과 어긋난다.

### 게이지는 테두리 두른 막대 셋이다

스무 칸이므로 **한 칸이 5%** 다. 5% 단위로 **올림**한다.

| 잔여 | 켜는 칸 |
|---|---|
| 87% | 18 |
| 83% | 17 |
| 99% | 20 (전부) |

**테두리를 줄마다 따로 긋고 등급색으로 칠한다.** 채운 부분에서는 막대와 하나로
보이고 빈 꼬리에서만 윤곽으로 드러난다. 그래서 여기까지가 100% 라는 것이
눈에 보인다.

안쪽은 이어진 막대다. 테두리가 끝을 알려주므로 칸을 갈라 그릴 이유가 없다.

| | 값 | 픽셀 (2배) |
|---|---|---|
| 칸 하나 | 1pt | 2px |
| 안쪽 높이 | 3pt | 6px |
| 테두리 | 0.5pt | 1px |
| 줄 사이 | 2pt | 4px |

전체 폭 21pt. 전부 정수 픽셀이라 번지지 않는다.

여기까지 오는 데 몇 번 돌았다. 처음에는 사각형 다섯을 눈금으로 갈라 그렸는데,
안쪽 여백이 반 픽셀에 걸려 뭉개졌다. 정렬을 고쳤더니 선이 낱낱이 보였고,
선을 붙였더니 이번에는 100% 가 어디인지 알 수 없었다. 테두리가 그 답이었다.

숫자 왼쪽에 `5h` 와 `1w` 를 붙인다. 셋째 줄은 자리가 없어 게이지만 남는다.

숫자는 오른쪽 정렬 상자에 넣지 않는다. 값이 짧으면 상자 안쪽 여백까지 더해져
라벨과의 사이가 두 배로 벌어진다. 상자를 걷어내고 간격 2.5pt = 5px 만 남긴다.
오른쪽 끝이 들쭉날쭉해지지만 게이지 자리는 바깥 세로 묶음이 잡아 주므로
흔들리지 않는다.

`100%` 는 네 글자다. 줄바꿈을 막아 둔다. 좁게 잡았더니 `%` 가 다음 줄로
떨어진 적이 있다.

### 색은 창마다 따로 붙는다

잔여 기준이다. 메뉴바를 흘깃 보는 목적이 "아직 돌려도 되나" 이므로 남은
쪽이 곧 답이다.

| 남은 양 | 색 | 뜻 |
|---|---|---|
| 50% 이상 | systemGreen | 여유 |
| 15% 이상 | 기본 라벨색 | 정상. 눈길을 끌지 않는다 |
| 5% 이상 | systemYellow | 주의 |
| 5% 미만 | systemRed | 소진 |

도트는 시스템 색을 그대로 못 쓴다. 1pt 짜리 점은 안티에일리어싱에 색이
씻겨서 면으로 칠할 때 멀쩡하던 값이 점으로는 흐려 보인다. 그래서 막대 전용
색을 따로 두고 **채운 칸을 빈 칸보다 굵게** 그린다. 색보다 무게 차이가 먼저
읽힌다.

### 칸 크기를 먼저 정한다

처음에는 폭 52pt 를 칸 수로 나눴다. 칸이 2.89pt 가 되어 픽셀 격자에 안 맞고,
그러면 안티에일리어싱에 번져서 또렷한 사각형이 아니라 뭉개진 점처럼 보인다.

거꾸로 한다. 칸과 간격을 정수 포인트로 고정하고 폭은 결과로 나온다.

| | 칸 | 간격 | 칸 수 | 폭 |
|---|---|---|---|---|
| 메뉴바 | 2x2 | 1 | 17 | 50pt |
| 팝오버 | 4x6 | 2 | 29 | 172pt |

빈 칸은 높이만 절반으로 줄인다. 폭까지 줄이면 격자가 흔들려 보인다.

### 라벨을 이미지로 굽는다

`MenuBarExtra` 는 라벨 뷰를 템플릿으로 그린다. 그대로 두면 색이 전부 날아가
등급을 구별할 수 없다. `ImageRenderer` 로 구운 뒤 `isTemplate` 을 꺼야 색이
남는다.

**대신 색이 구울 때 박힌다.** 적응형 색을 못 쓰므로 지금 메뉴바가 밝은지
어두운지 보고 그리고, 시스템 외양이 바뀌면 다시 구워야 한다. 그러지 않으면
다크 메뉴바에 검은 글씨가 얹혀 안 보인다. 실제로 처음에 그랬다.

## 4. 팝오버

너비 340pt, 안쪽 여백 14pt.

```
  clf                                       [갱신] [종료]

  * NAVER_TEAM_40  [team] [여유]              사용 중
      5시간      ::::::::::::::::::::::::  91%
                 3시간 48분 뒤
      주간 전체   ::::::::::::::::::::      84%
                 5일 3시간 뒤
      주간 모델별 :::::::::::::::::::::::   99%
                 5일 3시간 뒤

    Naver
      앱에서 이 계정을 한 번 열면 사용량이 읽힌다

  설정                                       02:13 갱신
```

리셋 문구는 값 옆이 아니라 **아랫줄**에 둔다. 한 줄에 넣으면 값과 시각이
눈싸움을 한다.

### 하루를 넘으면 시각도 적는다

```
5시간      리셋: 1시간 26분 뒤
주간 전체   리셋: 5일 1시간 뒤 (금요일 오전 5:59)
주간 Fable 리셋: 5일 1시간 뒤 (금요일 오전 5:59)
```

창이 안 열렸으면 `리셋:` 을 안 붙이고 `창 안 열림` 만 쓴다. 리셋할 것이
아직 없다.

`5일 1시간 뒤` 만으로는 그게 언제인지 감이 안 온다. 하루 안쪽이면 남은
시간만으로 충분하고 괄호는 잡음이다. 경계는 24시간이고, 정확히 24시간은
아직 넘은 것이 아니다.

**로케일은 한국어로 못박는다.** 화면 글자가 전부 한국어인데 시각만 시스템
로케일을 따르면 `5일 1시간 뒤 (Friday 6:00 AM)` 이 된다. 실제로 그렇게
나왔다. 시간대는 시스템을 따른다. 그건 사용자가 어디 있는지의 문제지
언어가 아니다.

형식도 우리가 정한다. `setLocalizedDateFormatFromTemplate` 에 맡겼더니
ko_KR 이 요일을 괄호로 감싼 형식을 돌려줘 `((금요일) 오전 5:59)` 가 됐다.
우리가 이미 괄호를 치고 있어 겹친 것이다.

### 게이지는 알약 하나다

```
5시간      +----------------------------------------+
           |  88%   ( ==================------- )   |
           +----------------------------------------+
```

숫자와 게이지가 **한 알약 안에** 있다. 바깥 알약을 등급색으로 꽉 채우고
오른쪽 안쪽을 파낸다. 파낸 자리 안에 다시 등급색으로 채우고, 숫자는 왼쪽
등급색 위에 그대로 얹는다.

처음에는 숫자 알약과 게이지 알약을 따로 그렸다. 시안을 잘못 봤다. 둘은
떨어진 도형이 아니라 하나다.

**파낸 자리를 배경색으로 칠하지 않고 `destinationOut` 으로 뚫는다.** 팝오버
배경은 단색이 아니라 vibrancy 재질이라 색으로 흉내내면 어긋난다.

파낸 자리와 채움 사이에 틈을 둔다. 없으면 가득 찼을 때 테두리가 사라져
100% 와 그냥 칠한 막대가 구별이 안 된다. 1% 라도 남았으면 채움이 보이게
최소 폭을 준다. 0 으로 그리면 소진과 같아진다.

높이 18pt, 숫자 자리 44pt, 파낸 자리 여백 2.5pt, 채움 여백 1.5pt.

숫자는 **전부 검정**이다. 참조 시안은 흰 글자인데 노랑 위에서 거의 안 보인다.
노랑은 잔여 5-15% 구간이라 바로 그때 읽혀야 하는 색이다. 정상 구간은 등급색
대신 회색으로 칠한다. 눈길을 끌지 않아야 한다.

상태 배지는 정상일 때 안 붙인다. 늘 켜져 있으면 안 읽힌다.

막대에 무엇이 뜨든 팝오버에는 켜 둔 계정이 전부 나온다.

사용률 0% 인 창은 리셋 시각이 없다. `-` 로 얼버무리지 않고 `창 안 열림`
이라고 쓴다. 관측하지 못한 것과 0으로 관측한 것은 다르다.

읽기에 실패해도 이전 값을 지우지 않는다. 한 번 실패했다고 화면을 비우면
사용자가 알고 있던 것까지 잃는다.

### 단추 자리

| 자리 | 무엇 |
|---|---|
| 우측 상단 | 새로고침, 설정(톱니) |
| 우측 하단 | 종료. 붉은색 |
| 좌측 하단 | 마지막 갱신 시각 |

설정이 좌측 하단에 작은 글자로 있으면 안 보인다. 자주 쓰는 것은 위로,
되돌릴 수 없는 것은 아래로 떼어 놓고 색으로 못박는다.

### 시안과 일부러 다르게 한 것

| 시안 | 지금 | 왜 |
|---|---|---|
| 우선순위 목록, 최근 활동, 일시 중지, 연결됨 | 없음 | 프록시 기능이다. [00 범위](00-scope.md) |
| 머리에 테마 토글 | 새로고침 | 테마는 시스템을 따른다. 앱이 정할 일이 아니다 |
| 전환 배너 | 없음 | 전환을 안 한다 |

셋째 줄 이름은 `주간 Fable` 이다. API 는 `scope: null` 을 주지만 데스크톱 앱이
`Weekly - Fable` 로 부르는 줄이므로 사용자가 아는 이름을 쓴다. 서버가 모델을
알려주기 시작하면 그 값으로 바꾼다.

## 5. 설정

팝오버 안에서 접었다 편다. 창을 따로 띄울 만큼 항목이 많지 않다.

- 메뉴바에 표시할 계정: 범위를 고르는 칸과 계정 목록을 한 묶음으로 둔다.
  둘은 한 가지를 정하는 짝인데 떼어 놓으면 목록이 무엇을 정하는지 안 보인다.
  목록 밑 한 줄은 고른 칸에 따라 바뀐다. `설정에서 지정한 계정` 이면 목록이
  곧 막대이고, `창이 열려있는 계정만` 이면 목록은 막대를 안 건드린다는 것을
  그 자리에서 알린다. 시안은 [settings-group-mockup.html](settings-group-mockup.html)
- 막대 범위: `창이 열려있는 계정만` / `설정에서 지정한 계정`.
  **두 항목의 기준이 다르다.** 앞은 지금 창이 떠 있는지를 보고, 뒤는 사용자가
  목록에서 켰는지를 본다. 그래서 앞은 숨김 목록을 안 본다. 창이 열린 계정을
  꺼 뒀다고 막대에서 빼면 화면에 떠 있는 것과 막대가 어긋난다
- 게이지 방향: `남은 용량` / `사용률`. 숫자와 채움이 함께 뒤집히고 색 등급은
  잔여 기준 그대로다. gauge-direction-mockup.html
- 계정마다 체크박스와 위아래 화살표

바뀌는 즉시 `~/Library/Application Support/clf/desktop.json` 에 쓰고 화면에
반영한다. 확인 단추가 없다.

순서를 아직 안 정한 상태에서 화살표를 누르면, 지금 보이는 차례를 그대로 받아
거기서 한 칸 옮긴다. 사용자가 본 것과 다른 순서로 튀지 않는다.

## 6. 실기기에서 확인한 것

메뉴바 앱은 눈으로 봐야 한다. 그런데 이 기계에는 Bartender 5 가 있어서 새 항목이
숨김 영역으로 들어간다. 접근성 API 로 확인했다.

```
osascript -e 'tell application "System Events" to tell process "clf" \
  to return value of attribute "AXTitle" of menu bar item 1 of menu bar 2'
-> 84%
```

`clfctl desktop usage --active` 가 같은 숫자를 낸다. 두 경로가 일치한다.

팝오버 자체는 화면 밖에 떠서 캡처가 안 됐다. 접근성 API 로 창을 화면 안으로
옮긴 뒤 찍었다.

```
osascript -e '... set position of window 1 to {300, 120}'
screencapture -x -R 280,100,360,440 popover.png
```

### 단추 이름

`Image(systemName: "chevron.up")` 에는 읽을 글자가 없다. 보이스오버가 아무 말도
못 한다. 전부 `accessibilityLabel` 을 붙였다.

AppleScript 의 `title of button` 은 `missing value` 를 준다. SwiftUI 가 이름을
`AXAttributedDescription` 에 넣는데 AppleScript 가 그걸 못 읽기 때문이다.
접근성 API 로 직접 읽으면 나온다.

```
AXButton  ->  설정 열기
AXButton  ->  지금 새로고침
AXButton  ->  clf 종료
```

없는 것과 못 읽는 것은 다르다. 도구가 안 보여준다고 없다고 적으면 안 된다.

## 7. 로그인 항목

`SMAppService.mainApp` 으로 등록한다. 헬퍼 번들도 launchd plist 도 필요 없다.

### 실측으로 잡은 것

**한 번도 등록한 적이 없으면 `.notRegistered`(0) 가 아니라 `.notFound`(3) 가 온다.**

```
PROBE status=3 path=/Users/cpm4/Applications/clf.app
PROBE register ok -> 1
```

이름만 보고 `.notFound` 를 "등록 불가" 로 읽었더니 체크박스가 처음부터 꺼진 채
잠겼다. 아무도 이 기능을 못 쓴다. 처음 상태가 그것이므로 `.off` 로 옮긴다.

진짜 불가능한 경우는 시스템에 묻지 않고 자리로 판별한다.

```swift
public static func isStableLocation(_ path: String) -> Bool {
    let volatile = ["/.build/", "/DerivedData/", "/Downloads/", "/tmp/"]
    guard !volatile.contains(where: { path.contains($0) }) else { return false }
    return path.contains("/Applications/")
}
```

`.build` 안에서 돌면 `make-app.sh` 가 다음 빌드에 번들을 지운다. 승인을 받아도
헛일이라 미리 막고 이유를 말한다. `scripts/install-app.sh` 가 `~/Applications`
로 옮긴다. 관리자 권한이 필요 없는 자리다.

### 승인 대기를 켜진 것으로 그리지 않는다

`.requiresApproval` 은 등록은 됐고 사용자가 시스템 설정에서 허용해야 하는
상태다. 체크된 것처럼 그리면 다음 부팅에 안 뜨는데 사용자는 이유를 모른다.
따로 표시하고 설정 화면을 열어주는 단추를 붙인다. 경로를 말로 설명하는 것보다
낫다.

우리가 원한 값이 아니라 시스템이 답한 값을 그린다. 등록이 승인 대기로 떨어질
수 있다.

## 8. 429

만들다가 만났다. Usage API 는 짧은 시간에 여러 번 부르면 429 를 준다.
개발 중에 앱을 몇 번 껐다 켜니 세 계정이 전부 막혔다.

```
NAVER_TEAM_40   Usage API HTTP 429
NAVER_TEAM_52   Usage API HTTP 429
```

두 가지를 고쳤다.

**말을 바꿨다.** `Usage API HTTP 429` 는 사용자가 할 수 있는 일을 안 알려준다.
`요청이 너무 잦다. 잠시 뒤 다시 읽는다` 로 쓴다.

**물러선다.** 429 는 실패와 다르다. 서버가 그만 물어보라고 한 것이다. 5분마다
계속 두드리면 창이 안 열린다. 한 번만 받아도 곧바로 15분으로 늘리고 풀리면
바로 돌아온다.

| 상황 | 주기 |
|---|---|
| 값이 변하고 있다 | 5분 |
| 세 번 연속 그대로 | 10분 |
| 못 읽었다 | 5분 (돌아오는 걸 빨리 알아야 한다) |
| **429** | **15분** |

읽기 실패와 429 를 가르는 것이 요점이다. 못 읽는 것은 빨리 되물어야 하고,
막힌 것은 물러나야 한다. 막힌 동안 값이 그대로인 것도 조용한 게 아니므로
연속 횟수를 세지 않는다.

앱이 정상으로 쓰는 주기는 5분에 계정 셋이라 여기 걸릴 일이 없다. 걸린 것은
개발 중 반복 실행 탓이다. 그래도 걸렸을 때 무엇을 하는지는 정해 둬야 한다.

## 9. 팝오버를 열 때마다 읽으면 안 된다

만들다가 두 번째로 429 를 만났다. 이번에는 원인이 분명했다.

```swift
.task { await model.refresh() }     // 팝오버가 뜰 때마다
```

**읽기 하나에 요청이 계정 수만큼 나간다.** 계정 셋이면 여닫기 다섯 번에
스무 건이다. 제동이 하나도 없었다.

### 문을 하나 둔다

`RefreshPacer` 와 하는 일이 다르다. 페이서는 **얼마나 자주 볼지**를 정하고,
`ReadGate` 는 **지금 눌러도 되는지**를 정한다.

| | |
|---|---|
| 사람이 유발한 읽기 | 60초 안에 또 부르면 안 읽는다. 화면에 방금 값이 이미 있다 |
| 주기 루프 | 문을 안 거친다. 자기 시계를 따른다 |
| 429 뒤 | 15분. **주기 루프도 세운다.** 서버가 그만 물어보라고 한 것이다 |

정숙 구간에서는 아무 말도 안 한다. 방금 읽어서 안 읽은 것은 알릴 일이
아니고, "요청이 몰렸다" 는 말은 사실도 아니다. 429 일 때만 사유를 띄운다.
그때는 값이 낡은 채로 멈춰 있는 이유가 되기 때문이다.

### 계정 이름은 한 번만 묻는다

이름은 안 바뀌는데 매번 물어서 읽기당 요청이 하나씩 더 나갔다. 캐시한다.
계정 셋이면 4건에서 3건으로 준다.

## 10. 실패해도 알던 값을 지우지 않는다

"자꾸 요청이 너무 잦다는 메시지가 뜨면서 아무것도 안 보인다" 는 보고.

한 계정이 429 를 맞으면 `DesktopReader` 가 빈 `limits` 를 담은 `OrgUsage` 를
만들고, 모델이 그걸로 갈아치웠다. 방금까지 보이던 숫자가 통째로 사라졌다.

`reader.read()` 자체가 던지는 경우는 막아 뒀는데, **계정 하나가 실패해도
읽기는 성공**이라 그 방어를 안 탔다.

```swift
public func mergeKeepingLastGood(fresh: [OrgUsage], previous: [OrgUsage]) -> [OrgUsage]
```

**값은 옛것을 쓰고 사유는 새것을 남긴다.** 값만 남기면 사용자가 옛 값을 지금
값으로 믿는다. 낡은 카드는 흐리게 그리고 아래에 `갱신 못 함` 과 이유를 붙인다.

처음부터 못 읽은 계정에는 물려줄 값이 없다. 그때는 지금처럼 사유만 나온다.
**모르는 것과 낡은 것과 0인 것은 서로 다르다.**

## 11. 계정 전환을 따라가는 값이 따로 있다

앱에서 계정을 바꿨는데 메뉴바가 한참 옛 계정을 가리켰다.

원인이 둘이다.

**갱신 주기의 지문에 활성 계정이 없었다.** 사용률만 담았으므로 계정만 바뀌고
숫자가 그대로면 조용한 것으로 보고 주기를 10분으로 늘렸다. 전환은 활동이다.
지문에 넣었다.

**주기를 기다릴 이유가 없었다.** 활성 계정은 로컬 쿠키에 있다. 사용량과 달리
**네트워크를 안 타므로 자주 물어도 공짜다.** 5초마다 본다.

### 표시는 먼저, 숫자는 나중에

바뀐 것을 알았을 때 할 일이 둘인데 값이 다르다.

| | 비용 | 언제 |
|---|---|---|
| `사용 중` 표시 옮기기 | 공짜. 로컬 값이다 | 곧바로 |
| 사용량 다시 읽기 | 요청이 계정 수만큼 | 문이 열리면 |

그래서 표시부터 옮기고 숫자는 뒤따라온다. 화면이 곧바로 사실을 말하면서
요청은 안 늘어난다.

```swift
public func reassignActive(to uuid: String?, in orgs: [OrgUsage]) -> [OrgUsage]
```

모르는 계정으로 옮겨갔으면 아무것도 활성이 아니다. 엉뚱한 곳에 표시를
남기느니 없는 편이 낫다.

첫 관측은 전환이 아니다. 시작할 때 도는 읽기와 겹치면 요청만 두 배다.

## 리셋 줄의 진행률

리셋 줄은 남은 시간 앞에 **그 창이 얼마나 지났는지**를 적는다.

```
리셋: 39%, 4일 6시간 뒤 (금요일 오전 6:00)
리셋: 97%, 10분 뒤
```

남은 시간만 보면 창의 어디쯤인지 모른다. 5시간 창의 10분과 주간 창의 10분은
뜻이 아주 다르다.

**방향은 게이지 설정을 따른다.** 지난 시간은 시간의 사용률 쪽이다.

| 설정 | 게이지 | 리셋 | 리셋 시점 |
|---|---|---|---|
| 사용률 | 3% | 5% | 100% |
| 남은 용량 | 97% | 95% | 0% |

게이지가 남은 용량을 세는데 리셋만 지난 비율을 세면 한 창을 두고 두 숫자가
반대로 움직인다. 그래서 100% 의 뜻이 설정마다 뒤집히지만, 어느 쪽이든 옆
게이지와 같은 방향이라 화면 안에서 어긋나 보이지 않는다.

**창 길이는 추정한다.** 서버는 리셋 시각만 주고 창 길이는 안 준다.

| 창 | 길이 | 근거 |
|---|---|---|
| 5시간 | 5시간 | 이름 그대로. 첫 사용에서 5시간 뒤 리셋 |
| 주간 전체 | 7일 | 리셋이 매주 같은 요일 같은 시각이다 |
| 주간 Fable | 7일 | 위와 같다 |

서버가 창 길이를 바꾸면 이 숫자만 틀리고 남은 시간은 그대로 맞는다.
아직 안 열린 창은 리셋 시각이 없으므로 진행률도 안 붙이고 `창 안 열림` 만
적는다. 시계가 어긋나 창 길이보다 더 남는 경우가 있어 0 과 100 사이로 가둔다.

시안은 [reset-progress-mockup.html](reset-progress-mockup.html) 과
[reset-direction-mockup.html](reset-direction-mockup.html).
