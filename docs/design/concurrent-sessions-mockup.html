한 폴더에 세션 여럿 - 알리는 방법

세션은 계정을 건너가지만 작업 트리는 안 옮겨진다. 그래서 한 체크아웃에 편집자가 여럿 생기고, 지금은 그것을 아무도 모른다. 13 문서 12절

세 자리에서 알릴 수 있다. 세션에게(1), 사용자에게(2), 그리고 어긴 상태를 찾아내서(3). 방식마다 시안을 두고 권장을 표시했다.

1. 세션에게 알린다 (화면에 안 뜬다)

이 묶음은 사용자 화면이 아니다. SessionStart hook 의 출력은 세션 컨텍스트로 들어가고, 사용자가 보는 것은 hook 이 돌았다는 표시뿐이다. 받는 쪽은 파일을 실제로 고치는 모델이다.

그래도 값이 있다. 이번에 남의 작업을 안 건드린 것은 모델이 스스로 git status 를 돌려봤기 때문이고, 이건 그것을 운에서 기본값으로 바꾼다. Vim 이 .swp 로 하는 것과 같다. 막지 않고 누가 잡고 있는지 말한다. 설치 자리는 clfctl settings install 이 이미 쓰는 ~/.claude/settings.json 이다.

방식 A. 한 줄

clf 이 폴더에 다른 세션 2개가 열려 있다

가장 싸고 안 거슬린다. 다만 무엇을 하라는 말이 없다. 이 한 줄로는 모델이 그냥 지나칠 수 있다.

방식 B. 누구인지 말한다권장

clf 이 작업 폴더를 쓰는 세션이 2개 더 있다 Clauly 도구를 GUI 기반으로 변환하기 3분 전에 씀 TEAM_40 게이지 잉크와 깊이 방금 씀 TEAM_52 커밋 안 된 변경 12개가 섞여 있다. 고치기 전에 git status 로 무엇이 남의 것인지 가른다.

이름과 마지막으로 쓴 시각을 말한다. 9절이 지운 자리에서 세운 규칙과 같다. 몇 개인지가 아니라 무엇인지 말하고, 상태만 찍지 않고 무엇을 하면 되는지 같이 적는다. doctor 가 이미 그렇게 한다.

살아 있는 신호는 레코드가 아니라 트랜스크립트 파일의 mtime 이다. 실측에서 레코드의 lastActivityAt 은 22:51 인데 그 세션은 22:58 에 일하고 있었다.

방식 C. 파일까지 짚는다나중

clf 겹치는 파일이 있다 Sources/ClfApp/BarLabel.swift 다른 세션이 4분 전에 고쳤다 Sources/ClfApp/UsageModel.swift 다른 세션이 방금 고쳤다

가장 정확하다. 그런데 어느 세션이 어느 파일을 고쳤는지 알려면 트랜스크립트를 뒤져야 하고 실측 88MB 짜리가 있다. 세션을 열 때마다 하기엔 무겁다. B 를 먼저 넣고 필요해지면 온다.

2. 팝오버에서 알린다

Google Docs 가 접속자를 보여주는 것과 같은 갈래다. clf 은 이미 SessionSummary 에 folder 를 갖고 있어 데이터가 다 있다.

방식 A. 계정 줄에 배지안 맞다

NAVER_TEAM_40 team여유 기본세션 2
NAVER_TEAM_52 team여유 창 실행중세션 1

9절의 배지 문법에는 맞다. 그런데 겹침은 계정에서 나지 않고 폴더에서 난다. 계정 줄에 붙이면 같은 계정 세션 둘이 서로 다른 폴더에 있을 때도 경고처럼 보인다. 화면이 데이터와 어긋난다.

방식 B. 겹치는 폴더만 보여준다권장

NAVER_TEAM_40 team여유 기본
NAVER_TEAM_52 team여유 창 실행중

겹치는 작업 폴더

clf 세션 3 커밋 안 된 변경 12개

겹침이 나는 단위 그대로 보여준다. 폴더마다 세션이 하나뿐인 평소에는 이 묶음이 아예 안 나타나서 조용하다. 있을 때만 나타나는 것이 알림의 자리이고 이 자리는 알림이 맞다.

방식 C. 넘기기 직전에 잡는다권장, B와 함께

세션 넘기기
! clf 폴더에 세션이 3개 있다. 이 대화를 넘겨도 나머지 둘은 같은 파일을 계속 고친다. 넘기기 전에 커밋해 두면 섞이지 않는다.

기본 창은 재시작 전까지 이 대화가 목록에 남아 있고, 그 줄을 누르면 열린다. 그러면 두 창이 같은 대화에 쓴다. 넘긴 뒤 기본 창을 다시 띄우는 편이 안전하다.
Clauly 도구를 GUI 기반으로 변환하기 clf · 3분 전
게이지 잉크와 깊이 clf · 방금
커밋 먼저 하기 1개 넘긴다

결정하는 순간에 말한다. 넘기는 그 순간이 한 트리에 창이 둘 되는 순간이라 여기가 제일 늦게까지 유효한 자리다. B 와 겹치지 않는다. B 는 평소에 알려주고 이쪽은 되돌리기 전에 잡는다.

커밋 먼저 하기 는 우리가 커밋하는 것이 아니라 창을 닫고 그쪽에서 하라는 안내다. 남의 작업 트리에 우리가 커밋하면 안 된다.

3. 어긴 상태를 찾아낸다

11절은 한 대화를 한 계정만 가리키게 정했는데 지금 디스크가 그것을 어기고 있고 아무도 안 잡는다. git fsck 와 brew doctor 가 있는 자리다.

방식 A. doctor 에 한 줄 더한다권장

$ clfctl doctor 항목 상세 ok 데이터 디렉토리 /Users/cpm4/.clf ok Claude 설정 디렉토리 /Users/cpm4/.claude ok 등록된 조직 3개, 자동 전환 2개 no 대화-계정 짝 3개가 두 계정에 겹쳐 있다. clfctl desktop dedupe 1개 항목이 준비되지 않았다

이미 있는 자리에 한 줄이다. 새 화면도 새 개념도 없다. DoctorCommand 의 규칙(상태만 찍지 않고 무엇을 하면 풀리는지 같이 적는다)을 그대로 따른다. 검사는 계정 폴더를 훑어 같은 cliSessionId 를 세는 순수 함수라 테스트가 쉽다.

방식 B. 설정 아래 줄자리가 안 맞다

멀티 인스턴스

정보 삭제 316MB 지운다
대화-계정 짝 3개 겹침 정리한다

사용자가 볼 자리에 있다는 것이 장점이다. 그런데 겹치는 일은 평소에 없어서 빈 줄이 놀고, 있을 때만 나타나게 하면 그건 설정이 아니라 알림이다. 9절이 지우기를 설정에 둔 것은 언제나 할 수 있는 일이기 때문이다. 이쪽은 다르다.

방식 C. 넘기기 창에서 왜 막혔는지 말한다A의 보완

세션 넘기기
Clauly 도구를 GUI 기반으로 변환하기 두 계정에 겹쳐 있어 못 옮긴다. clfctl doctor 로 본다
게이지 잉크와 깊이 clf · 방금

11절은 이미 이름이 겹치면 아무것도 안 바꾸고 멈춘다. 지금은 왜 멈췄는지가 화면에 없다. 이 시안은 그 자리를 채운다. 다만 겹침 자체를 찾아내지는 못하므로 A 와 같이 간다.

넣는 순서. 사용자는 팝오버와 넘기기 창으로 일하므로 2C 와 2B 를 먼저 한다. 2C 는 되돌리기 전에 잡는 마지막 자리이고 2B 는 평소에 알려주는 자리다. 그다음이 3A 이고(작고 테스트가 쉬우며 지금 실제로 깨져 있는 상태를 잡는다), 1B 는 그 뒤 보험이다. 1C 는 열어 둔다.

안 한 결정. 세션마다 git worktree 를 주는 것이 제대로 된 격리다. worktree 마다 SwiftPM .build 가 새로 생기고 나중에 병합 부담이 오므로 여기서는 다루지 않았다.
