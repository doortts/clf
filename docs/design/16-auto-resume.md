# 16. 자동 재개

리밋 소진으로 멈춘 Claude Code CLI 세션을, 창이 리셋되고 3분 뒤에 자동으로
이어 돌린다. UI 시안은 docs/design/auto-resume-mockup.html 에 있다.

## 1절. 배경

리밋에 걸리면 작업이 그 자리에서 멈춘다. 데스크톱 앱의 deep link
(`claude-cli://open`)는 새 세션만 열 수 있고 기존 세션을 재개하지 못한다.
반면 CLI 는 `claude --resume <세션ID> -p "<프롬프트>"` 로 세션을 이어
돌릴 수 있고, 세션 기록은 `~/.claude/projects/` 에 있어 clf 가 읽을 수 있다.

clf 는 이미 계정마다 창별 리셋 시각(`resetsAt`)을 알고 있으므로, 리셋 시점을
기다렸다가 CLI 를 실행하는 다리만 놓으면 된다.

## 2절. 동작 규칙

상태는 넷이다. 토글이 켜져 있는 동안 아래를 반복한다.

```
대기 --(5시간 또는 주간 전체 창 잔여 0)--> 예약
예약 --(리셋 시각 + 3분 도달)------------> 점검
점검 --(두 창 모두 여유)-----------------> 실행 --> 대기
점검 --(여유 없음)-----------------------> 보류 --> 대기
```

- **대기**: 설정에서 고른 계정의 `session`(5시간)과 `weekly_all`(주간 전체)
  창을 지켜본다. 기존 사용량 읽기 주기에 얹으므로 요청이 늘지 않는다.
- **예약**: 소진된 창 중 **가장 늦게 풀리는 창**의 `resetsAt` + 3분에
  타이머를 건다. 알림(`UsageAlerts`)과 같은 기준이다. 서버의 `resets_at` 은
  읽을 때마다 초 단위로 흔들리지만(UsageAlert.swift 주석) 3분 여유가 흡수한다.
- **점검**: 타이머가 울리면 사용량을 다시 읽는다. 예약 시점의 값은 낡았다.
- **실행 / 보류**: 3절의 조건으로 가른다. 어느 쪽이든 한 번 지나가면 대기로
  돌아가고, 다음 소진에서 다시 예약된다.

같은 리셋에 두 번 실행하지 않는다. 실행/보류를 결정한 리셋 시각을 기억해
두고, 같은 시각(분 단위 반올림)으로는 다시 예약하지 않는다.

`weekly_scoped`(주간 Fable)는 보지 않는다. 모델 하나에만 걸리는 창이라
소진돼도 다른 모델로 이어갈 수 있고, 재개를 막을 이유가 못 된다.

## 3절. 재개 조건: 여유 판정

점검 시점에 5시간과 주간 전체 **두 창 모두 잔여 30% 이상**이어야 실행한다.
30% 는 화면 색의 `여유`(ample) 경계와 같은 값이다. 새 기준을 만들지 않고
사용자가 이미 초록으로 읽는 그 경계를 쓴다.

- 5시간 창은 리셋 직후라 사실상 항상 통과한다. 실질 관문은 주간이다.
- 주간이 30% 미만이면 **보류**한다. 자동으로 도는 작업이 주간 잔여를 갉아
  사람이 쓸 몫을 잡아먹으면 안 된다. 보류 사유는 알림과 설정 화면에 남긴다.
- 값을 못 읽었거나(`hasUsage` 거짓) 낡았으면(`isStale`) 실행하지 않는다.
  모르는 채로 돌리는 것보다 안 돌리는 쪽이 싸다.

## 4절. 실행

```
claude --resume <세션ID> -p "<프롬프트>"
```

- 작업 디렉토리는 세션 기록에 적힌 `cwd` 를 쓴다.
- `-p`(print 모드)라 창이 뜨지 않고 한 턴을 돌고 끝난다. 결과 요약은
  알림으로 보낸다: 성공이면 `이어서 실행했습니다`, 실패면 exit code 와
  stderr 첫 줄.
- CLI 경로는 `~/.local/bin/claude` 를 먼저 보고 없으면 `PATH` 에서 찾는다.
  없으면 설정 화면에 그 사실을 적고 토글을 흐리게 둔다.
- 프로세스는 AltLauncher 처럼 기다리지 않고 띄우되, 종료 알림을 위해
  terminationHandler 만 단다.

## 5절. 계정 선택과 CLI 로그인

설정의 계정 선택은 **어느 계정의 한도를 지켜볼지**를 정한다. 실제 재개는
CLI 가 자기 로그인 계정으로 돈다. 둘이 다르면 엉뚱한 계정의 리셋에 맞춰
남의 한도로 실행된다.

1단계에서는 이 사실을 설정 화면에 한 줄로 적는 데서 멈춘다
(`CLI 가 이 계정으로 로그인돼 있어야 합니다`). CLI 로그인 계정을 읽어
일치 여부를 검사하는 것은 `~/.claude.json` 형식 확인이 필요해서 뒤로 미룬다.

## 6절. 세션 선택

`~/.claude/projects/*/*.jsonl` 을 훑어 최근 수정 순으로 보여준다.

- **제목**: 기록 첫머리의 `custom-title` 레코드. 없으면 첫 사용자 메시지
  앞부분을 자른다.
- **프로젝트**: 레코드의 `cwd` 필드. 디렉토리 이름(`-Users-...`)을 거꾸로
  풀지 않는다. 경로에 `-` 가 든 프로젝트에서 모호해진다.
- 목록은 최근 10개로 자른다. 더 오래된 세션을 자동으로 이어 돌릴 일은
  드물고, 필요하면 그 세션을 한 번 열어 mtime 을 올리면 된다.
- 파일이 사라진 세션(지워진 프로젝트)은 실행 시점에 걸러 알림으로 알린다.

## 7절. 설정 저장

`DesktopPreferences` 에 한 덩어리로 얹는다. nil 이면 꺼진 것이다.

```swift
public struct AutoResumePlan: Codable, Sendable, Equatable {
    public var orgUUID: String      // 한도를 지켜볼 계정
    public var sessionId: String    // 재개할 세션
    public var cwd: String          // 세션의 작업 디렉토리
    public var title: String        // 설정 화면 표시용
    public var prompt: String       // 기본 "이어서 진행해줘"
}
// DesktopPreferences.autoResume: AutoResumePlan?
```

세션 목록이나 상태는 저장하지 않는다. 목록은 열 때마다 훑고, 상태는
메모리에만 둔다. 앱을 껐다 켜면 대기부터 다시 시작한다.

## 8절. 구성 요소와 검증

| 자리 | 역할 |
|---|---|
| ClfDesktop/AutoResume.swift | 상태와 판정. 순수 함수로 두고 TDD |
| ClfDesktop/SessionScanner.swift | 세션 목록 읽기. 임시 디렉토리로 테스트 |
| ClfApp/UsageModel | 읽기 주기에 판정을 얹고 타이머와 프로세스 실행 |
| ClfApp/Views | 설정 구획과 상태 줄 |

판정 로직(소진 감지, 3분 계산, 여유 판정, 중복 실행 방지)이 전부
AutoResume.swift 의 순수 함수에 모이므로 시계와 사용량을 주입해 검증한다.

## 9절. 하지 않는 것

- **여러 세션 동시 재개**: 하나만. 여럿이 필요하다는 말이 나오면 그때 배열로.
- **재개 후 결과 확인**: 한 턴 돌리고 끝. 작업이 다 끝났는지는 판단하지
  않는다. 반복 재개가 필요하면 다음 소진-리셋 주기가 알아서 돈다.
- **deep link 로 데스크톱 창 열기**: 새 세션이 생겨 맥락이 끊긴다. CLI 재개로
  기록은 이어지므로, 데스크톱에서 보고 싶으면 사용자가 그 세션을 열면 된다.
- **여유 기준 설정 노브**: 30% 고정. 조절하고 싶다는 말이 나오면 그때 단다.
